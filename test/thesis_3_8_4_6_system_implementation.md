# 3.8 系統實作與介面設計

前述章節已分別說明 LSTM 量化預測、技術指標、新聞情緒分析、LLM 實體過濾與 Hybrid FinBERT 情緒分數之方法設計。本節不再重複各模型之理論與訓練細節，而是說明本研究如何將上述模組整合為一套可互動之投資輔助系統。系統以 Streamlit 作為前端介面，並以模組化方式串接資料擷取、模型推論、新聞情緒評估與自然語言說明產生流程，使使用者能以自然語言查詢個股或大盤標的，並取得量化訊號、新聞情緒與風險提示並列之分析結果。

整體流程可分為四個階段。第一階段為使用者意圖解析。使用者於 Streamlit 介面輸入問題後，系統透過 LLM 判斷該輸入是否屬於投資相關查詢，並解析股票代碼、公司名稱、查詢類型與風險偏好。若使用者詢問「台股」、「大盤」或「加權指數」，系統會將其歸類為市場指數分析；若輸入內容與投資無關，則停止後續模型流程並回覆提示訊息。

第二階段為市場資料與新聞資料擷取。系統依據解析出的標的代碼取得近兩年歷史股價資料，供技術指標計算與 LSTM 推論使用；同時根據公司名稱查詢近期 Google News 新聞，並於新聞進入情緒模型前先完成標題清洗、重複新聞排除與 LLM 實體關聯過濾。此階段的功能在於將價格資料與文字資料分別整理為可供模型使用的結構化輸入，並降低新聞資料中非目標公司或多實體雜訊對情緒分數造成的干擾。

第三階段為模型推論與訊號彙整。量化模組會將歷史價量資料轉換為技術指標與市場狀態特徵，並輸入 LSTM 集成模型產生預期報酬率、交易方向與市場狀態；新聞情緒模組則將通過 LLM 過濾之新聞標題輸入 Hybrid FinBERT，計算每則新聞之情緒分數，並彙整為近期平均市場情緒。兩類模型分別代表價格行為與新聞語意兩種不同訊號來源，系統不以其中任一模組取代另一模組，而是將其並列呈現，作為後續解釋與風險校準之依據。

第四階段為結果呈現與自然語言說明。系統將量化模型輸出、即時價格、技術狀態、新聞情緒分數、正負向新聞佐證與市場狀態資訊傳入 LLM，由 LLM 產生結構化文字分析。此處 LLM 並非作為單獨決策模型，而是作為解釋層，用以將多模組輸出轉換為使用者可理解的市場說明。當量化訊號與新聞情緒方向一致時，系統會指出兩者相互支持；當兩者方向不一致時，系統則提示信心下降、情緒過熱、誘多或短線波動等潛在風險。

因此，本研究之系統實作重點在於建立一條由「自然語言查詢」至「多模組模型推論」再到「可解釋化輸出」的完整流程。此流程使前述量化模型與情緒模型不僅停留於離線實驗結果，而能進一步整合至互動式應用情境中，協助使用者同時檢視價格面、技術面與新聞面訊號。

## 3.8.1 Streamlit 前端介面設計

本研究採用 Streamlit 建置互動式前端介面，以降低使用者操作門檻並提升模型結果之可解釋性。介面設計採對話式輸入與儀表板輸出並行的方式：使用者可直接於聊天輸入框中輸入自然語言問題，例如「台積電走勢如何？」或「大盤最近能不能追？」系統則自動解析標的並執行完整分析流程。此設計避免使用者必須手動輸入多項參數，也能保留自然語言互動的彈性。

系統側邊欄提供新對話建立與歷史紀錄切換功能，使使用者能在不同股票或不同查詢情境間保留分析脈絡。主畫面則以聊天訊息方式呈現系統回覆，並於每次分析完成後嵌入儀表板資料。儀表板主要分為三個分頁：核心數據與線圖、情緒新聞清單、量化模型參數。第一個分頁顯示預期報酬率、近期市場情緒與市場趨勢狀態，並以 K 線圖與收盤價折線圖呈現近一個月價格走勢；第二個分頁列出經過 LLM 過濾與 Hybrid FinBERT 分析後的新聞標題、情緒分數、正面命中詞與負面命中詞；第三個分頁則顯示量化模型輸出之原始 JSON 結果，包含預期報酬率、交易訊號、市場狀態與近一年最大回撤。

為使使用者理解系統正在執行的分析步驟，前端於分析過程中顯示進度狀態與各階段耗時，包括意圖解析、行情抓取、新聞抓取與情緒分析、量化模型推論等。此設計可提升系統透明度，使使用者理解最終報告並非單一模型直接生成，而是由多個資料與模型模組逐步整合而成。

## 3.8.2 自然語言分析與風險提示設計

本研究之系統設計強調可解釋性與風險揭露，而非直接提供絕對買賣建議。傳統量化系統常以數值、圖表或交易訊號呈現結果，雖有助於專業使用者判讀，但對一般投資者而言，單一指標或模型輸出可能不易理解。因此，本研究導入 LLM 自然語言說明模組，將量化預測、技術指標、新聞情緒與市場狀態整理為結構化分析報告，協助使用者理解目前市場訊號是否一致，以及是否存在潛在風險。

自然語言報告主要包含三部分。第一部分為情緒分析預測，系統根據 Hybrid FinBERT 計算之市場情緒分數，說明近期新聞偏多或偏空，並列出具代表性的正向與負向新聞佐證。第二部分為量化模型預測，系統呈現 LSTM 集成模型輸出之預測訊號、預期報酬率、市場狀態與最大回撤，並說明該結果是基於歷史價格、技術指標與波動特徵推論，而非由新聞情緒直接驅動。第三部分為綜合建議與風險提示，系統比較量化訊號與新聞情緒是否一致，若兩者同向，則表示目前市場訊號較為一致；若兩者分歧，則提示使用者留意信心下降、情緒過熱、誘多、軋空或短線波動等風險。

在風險提示設計上，系統採用信任校準（Trust Calibration）概念。若量化模型輸出買入或偏多訊號，但近期新聞情緒分數顯著偏負，系統會提示「技術量化訊號偏多，但近期市場情緒顯著偏空，建議保守評估」；若量化訊號偏空，但新聞情緒顯著偏多，系統則提示使用者留意軋空風險或誘多陷阱。此機制可避免使用者過度依賴單一模型結果，並促使其同時考量價格行為與新聞情緒之間的一致性。

因此，本研究介面設計不直接提供絕對買賣建議，而是將模型結果轉化為具脈絡的自然語言分析。此設計能降低模型黑箱感，使使用者在閱讀分析報告時，不僅知道系統輸出何種訊號，也能理解該訊號來自何種資料來源、是否受到新聞情緒支持，以及在訊號不一致時應如何評估潛在風險。

# 4.6 系統展示與應用情境分析

前述章節已說明系統架構、模型設計與各模組實驗結果，因此本節不再重複模型細節，而是以展示角度說明系統於實際使用情境中如何呈現分析結果。系統介面如 Fig. 4.X 所示，使用者可於 Streamlit 對話框輸入欲查詢之股票或台股指數，例如「台積電走勢如何？」或「台股大盤目前怎麼看？」系統完成分析後，會於同一畫面同步呈現量化模組結果、新聞情緒結果與 LLM 自然語言說明，使使用者能快速檢視不同訊號來源是否一致。

建議加入圖：Fig. 4.X. System demonstration of the Streamlit-based stock analysis interface.

在使用流程上，系統首先接收使用者之自然語言查詢，接著自動辨識標的並執行資料擷取與模型推論。分析完成後，介面會以儀表板方式呈現核心數值與圖表，並以文字報告補充說明模型結果。以查詢單一股票為例，若使用者輸入「台積電走勢如何？」，系統會呈現該標的之最新價格、預期報酬率、交易訊號、市場狀態與近一年最大回撤，作為量化模組輸出；同時也會列出近期經 LLM 實體過濾後的新聞標題、平均情緒分數、個別新聞 FinBERT 分數及正負向關鍵字命中結果，作為新聞情緒模組輸出。

建議加入圖：Fig. 4.X. User workflow and integrated output layout of the proposed system.

LLM 說明區則負責將量化結果與新聞情緒結果轉換為較易理解的自然語言分析。其輸出不是單獨取代模型判斷，而是將量化訊號、技術狀態、新聞情緒與代表性新聞整合為綜合診斷。例如當量化模型顯示偏多且新聞情緒亦為正向時，系統會說明兩者訊號相互支持；若量化模型偏多但新聞情緒偏空，或新聞情緒熱絡但量化模型偏保守，系統會降低建議強度並提示使用者留意訊號分歧。此設計使介面不僅呈現結果，也能說明結果之間的關係。

| 輸出項目 | 呈現內容 | 解讀功能 |
| --- | --- | --- |
| 最新價格 | 最近交易日收盤價 | 提供標的目前價格基準 |
| 預期報酬率 | LSTM 集成模型輸出之平均預期報酬 | 衡量短期量化預測方向與幅度 |
| 交易訊號 | 買入、賣出或觀望 | 將模型數值轉換為可理解之方向性訊號 |
| 市場狀態 | 強勢偏多、回檔整理或趨勢轉弱 | 說明標的目前所處價格環境 |
| 最大回撤 | 近一年最大回撤比例 | 呈現下行風險與歷史波動壓力 |
| 情緒分數 | -1 至 1 之平均新聞情緒 | 衡量近期新聞面偏多或偏空 |
| 新聞清單 | 經 LLM 過濾之新聞標題與情緒分數 | 提供情緒分數之文本佐證 |
| LLM 分析 | 綜合診斷、情緒分析、量化預測與風險提示 | 將模型結果轉換為自然語言說明 |

當量化訊號與新聞情緒不一致時，系統會於風險提示區明確標示分歧情形。例如量化模型顯示偏多，但近期新聞情緒明顯偏空時，系統會提醒使用者該標的可能存在消息面壓力，應降低追價信心；反之，若新聞情緒偏多但量化模型偏空，系統則會提示情緒過熱或短線反轉風險。透過此方式，系統將模型分歧轉化為可理解的風險提醒，避免使用者只依賴單一訊號做出判斷。

整體而言，本系統展示了量化模型、新聞情緒分析與互動式介面整合於投資輔助場景中的可行性。系統不以取代投資者決策為目的，而是透過資料整理、模型推論與自然語言說明降低資訊判讀成本，協助使用者更有效率地掌握市場狀態與潛在風險。
